# v0.4.2：非 UTF-8 构建日志不再阻止启动

## 问题与修复边界

v0.4.1 的 process::capture 被构建输出和机器可读输出共用。Maven 编译即使退出码为 0，标准输出含 GBK 字节仍会产生“输出不是 UTF-8；未按损坏路径执行”，从而阻止后续启动。这个错误并不证明项目路径已经损坏。

本次将进程捕获拆成两条明确路径：

- 结构化输出（仓库状态、路径、选择器 JSON 等）仍严格验证 UTF-8，不能用替换字符生成要执行的路径。
- 构建日志、版本说明与运行 stdout/stderr 只用于显示，允许按配置解码；构建成败仍由实际进程退出码判断。解码替换有提示，不把日志显示错误当编译失败。

默认自动模式优先 UTF-8，发现无效字节后采用 Windows 系统 ANSI 代码页对应编码；支持显式 UTF-8、GBK/CP936、GB18030、系统编码。自动模式是显示启发式，不是可靠的任意混合编码探测器。一个流内混合编码仍可能需要用户明确选择。

按流维护增量解码器，防止中文字符跨管道读取边界时损坏。未决定编码的尾部最多三字节；日志总量、单行和任务队列仍受既有上限限制。

## 配置与升级

旧配置没有 output_encoding 时默认为 auto。可在自动运行配置的高级选项或高级原始命令的构建选项中选择“日志编码”；保存保留原配置 ID 和实例引用。

不修改用户源文件编码、不强加 JVM file.encoding、不改变 chcp 或系统区域设置、不重命名项目目录。只处理外部进程返回的显示字节。异常结构化路径仍拒绝执行。

## 验证计划

保留 v0.4.1 后端、分组、批量操作、Maven 和界面回归。在 tests/encoding-042.py 中另外执行：实际非 UTF-8 构建输出、默认模式启动、GBK 逐字节 stdout/stderr、真实非零退出码与旧进程保留、配置重启持久化、中文路径和 Git 路径保护；Windows 额外使用真实 Maven + Java 8 + Spring Boot，在中文含空格目录下编译运行，并通过页面选择日志编码。

以 CI 的原始 JSON 报告和构建结果为准；本文件不预先声明测试通过。私有 PMS 工程和用户 Windows 11 桌面仍需要用户环境验收。
