# v0.3 Rust 本地执行器

本版本将真实执行器与 v0.2 演示页面分开：本机 Rust 服务提供自己的 Quasar 操作台；GitHub Pages 仍为清楚标注的模拟预览。原生运行包包含二进制与 web/，不要求用户安装 Rust 或为了控制台安装 Node.js。

## 用户操作

启动程序 → 浏览器自动打开 → Git / SVN 配置检查本机客户端 → 选择项目文件夹并确认信任 → 添加运行配置 → 添加多个实例 → 启停、更新、看日志与代码差异。

客户端优先级：项目指定路径 > 全局指定路径 > 自动发现。自动发现只检查 PATH 与常见安装目录，不全盘扫描。调用 --version 确认客户端能运行；手动路径失效会报错，不静默换用其他程序。支持 SVN 配置目录覆盖。

不自动安装 Git/SVN，不把 TortoiseSVN GUI 主程序误当 svn 命令行工具。认证沿用用户本机工具配置；不保存密码，不禁用 TLS 证书校验。含凭据的 URL userinfo 在界面中隐藏。

## 运行能力

- Windows Job Object / Unix 进程组管理受控程序和普通子进程。
- 同一配置共享构建，多个实例分别配置端口、额外参数和环境变量。
- {port} 替换进入实际命令参数，同时设置 PORT 环境变量。
- 构建后重启流程；构建失败不主动停止旧进程。并非 JVM 原地热替换。
- 仅在实例运行期间监听指定源目录。已有 Vite HMR / Node watch / 框架 reload 时应留空 No-ide 监听目录，避免双重重启。
- TCP 端口就绪检查，不等同于应用健康检查；无端口配置时仅表示进程启动。
- 真实 stdout / stderr 经有界缓冲和 WebSocket 显示，日志上限 512 KiB / 2000 条，网页最多渲染最近 120 条。

## 版本管理能力

读取真实 Git / SVN 状态、文本 Diff。Git 支持暂存、取消暂存、本地提交、origin 分支显式推送与仅快进拉取。SVN 支持添加选中文件、提交选中文件、更新。提交前显示文件集合、分支和真实目的地，生成 90 秒单次确认令牌，执行前重验状态及选中文件内容。

更新工作副本前要求先停止项目实例，且不允许未提交改动，避免构建一半更新的代码。不执行 force push、reset、revert 或自动丢弃文件。出现冲突阻止提交，不伪装解决成功。

## 安全和限额

仅绑定 127.0.0.1；Host / Origin 白名单；每次启动随机会话令牌，HTTP Bearer / WebSocket 首帧认证。没有项目文件下载接口，不把源目录作为静态站点公开。选择本机项目需要显式信任，构建脚本与 Git hooks 可能执行代码。

项目 32 个、配置/实例各每项目 32 个、仓库每项目 16 个；进程/命令输出有界；VCS 文件列表最大 2000 条，单次选择 200 个，确认内容合计 16 MiB；超限明确拒绝，不伪造完整结果。

普通环境变量会存入用户配置文件，因此机密建议使用外部凭据工具或进程继承环境，不要填写在普通变量表单中。应用输出可能自带秘密，分享日志前应检查。

## 明确未完成

- Java/Spring Boot 的专用增量构建及 JVM HotSwap；当前提供通用命令与模板。
- Android 设备枚举、ADB 安装与日志、原生应用热替换；目前只有构建命令模板。
- 分布式服务依赖图、远端执行器、自动工具链安装、clone / checkout。
- SVN 文件名包含 @、目录递归提交、复杂重命名/冲突可视化处理。
- 构建产物原子发布：第三方构建可能写共享输出目录，因此“旧进程未停止”不能保证应用依赖的所有磁盘文件未变化。
- 系统图形目录选择器的人工点击尚需真实桌面环境验证；无桌面 Linux 可通过 API 注册明确绝对目录。
- macOS / Windows 发布包未签名、公证；不声称经过商店或企业认证。

## 验证

原生工作流在 Linux x64、Windows x64、Apple Silicon Mac、Intel Mac 构建运行。tests/backend-smoke.py 使用一次性临时项目和本地 Git/SVN 服务器验证实际运行与仓库读写。tests/native-browser.py 使用 Chromium 验证真实前端到本地执行器。

通过与否必须以对应工作流日志和 JSON 报告为准，本文件不预先宣布所有测试通过。
