# v0.2 · 项目、多实例、目录选择与 Git / SVN

日期：2026-09-20。用户需求已归档；当前交付为前端操作预览，真实执行器待接入。

本文件修订 v0.1 中将“添加项目”直接创建为单个服务的模型。优先级：项目是组织单位，运行实例不是项目。

## 1. 项目与实例

项目持有目录引用、运行配置集合、代码仓库集合。每个运行配置持有语言 / 工具链、运行目录、公共构建与启动命令、监听范围和更新方式。实例引用配置，单独持有端口、启动参数、环境变量、运行状态与日志关联。

例如：商城项目包含网关配置、订单配置、用户配置、Vite 配置；订单配置可创建实例 01 与 02，端口不同，独立启停。分布式服务和相同服务多副本都不再要求重复创建项目。

前端支持每次创建 1～8 个实例，连续分配端口，冲突时阻止创建。这里仅校验已配置的端口，不宣称已检测操作系统端口占用。后续执行器需将端口正确映射到具体启动参数，不能只改显示值。

项目级启停、日志清理和运行记录仅影响当前项目。公共配置改变影响引用该配置的实例，实例参数不互相覆盖。最终执行器需支持构建任务共享、影响范围分析、按实例更新；前端流程模拟不等于已实现共享编译。

## 2. 目录选择

主操作是“选择文件夹”，不是强迫填写路径。创建时目录名自动作为默认项目名。运行配置默认继承项目目录，可另选工作目录。

浏览器预览优先调用 showDirectoryPicker，仅读取所选目录名称，不遍历、读取、上传或写入文件。目录取消无副作用。权限拒绝时展示解释并提供兼容目录选择。兼容方式可能枚举目录条目，必须提示，不应以“低占用”为由掩盖这项成本。

浏览器返回的目录名 / 句柄不能被伪造为本地绝对路径。当前不保留可用于执行的句柄；正式本地执行器负责系统目录对话框、安全目录引用与访问校验，连接后用户仍应点选而非手写路径。

从仓库获取支持 Git clone / SVN checkout 的交互入口，选择保存父目录和项目名。当前仅记录意图，不创建文件夹或下载仓库。

## 3. 版本管理属于项目

一个项目允许关联多个仓库根目录。每个根目录分别识别 Git / SVN、分支或修订版本、远端及本地变更；不得用一个项目总状态掩盖不同仓库。实例不重复管理同一份仓库。

Git 交互：查看工作区与暂存区 → 选文件暂存 → 提交说明 → 确认本地提交 → 独立确认推送。提交只消费已暂存文件，其他改动保留。显示未推送数量，明确提交去向；默认不自动推送。

SVN 交互：更新工作副本 → 查看 BASE 与本地 Diff → 勾选提交文件 → 确认直接提交服务器。没有 Git 暂存区和独立 push。未选文件保留在工作副本。

存在冲突时阻止提交、拉取或推送，提供清楚反馈；不得自动丢弃本地文件。当前预览保守阻止带未提交改动的拉取，这是产品策略，不是声称 Git 在所有情况下都不能带改动拉取。

## 4. Diff 与性能

前端按需计算当前示例文件的逐行差异，支持统一 / 并排视图、增加删除标记、行号和统计。Vue 文本插值展示源代码，不把代码作为 HTML 执行。

预览算法限制：双方合计 65,536 字符，各不超过 240 行，避免无限 O(n×m) 运算。超过上限展示提示。未实现二进制、图片、重命名相似度、逐块暂存以及同一文件同时存在已暂存和未暂存版本的完整语义；不应宣称完整 Git 客户端兼容。

真实执行器阶段应调用原生 Git / SVN 的结构化输出，按需读取有界差异，串行化写操作并进行状态快照校验。提交确认列出仓库、分支或修订、文件集合、说明及去向；禁止自动 force push、自动 reset 或提交所有文件。

凭据使用本机凭据管理，不把密码或 token 放在网页持久化、日志、命令行参数或提交文档中。认证、网络失败和冲突属于不同状态。拉取导致的文件变化应作为一批发布给运行调度器，不能边更新文件边启动半更新项目。

## 5. 本版边界

所有示例仓库、运行状态、版本、日志与 SCM 成功反馈均持续标注演示。用户自己创建的项目显示待检测 / 待连接，不套用示例 Diff。页面不会运行真实 Git / SVN 命令，不上传所选目录，也不会实际提交用户代码。
