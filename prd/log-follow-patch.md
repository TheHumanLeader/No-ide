# v0.4.2 日志自动滚动补丁

日期：2026-09-21。范围仅限真实操作台的日志显示，不改 Rust 后端、Maven 命令、运行环境和项目文件。

默认跟随最新日志；手动往上翻、PageUp 或关闭自动滚动时保留一份最多 1000 条的阅读快照，避免上游滚动缓冲淘汰旧行时跳动。只渲染最近 120 条。回到底部、End、恢复自动滚动或继续展示会追上最新输出。筛选、长行换行、尺寸变化、重新进入页面均处理自动定位。不使用 scrollIntoView 拉动外层页面，不增加常驻轮询。

补丁通过单独入口替换原生操作台的日志区域，其他操作和 API 仍使用 v0.4.2。若未来布局改变导致日志区域匹配失败，则明确报错，不降级成模拟界面。

验证入口：tests/log-scroll.py。使用真实临时 Python 进程输出，经现有 Windows 二进制、WebSocket、生产 Vue/Quasar 页面，检查实际 scrollTop。实际验证结果另行归档，当前文档不提前声明通过。

## 关于与 IDEA 启动内容的差异

当前 backend/src/launch.rs 中 spring-maven 在选中的模块工作目录执行 -DskipTests compile 和 spring-boot:run，没有自动从聚合根项目构建同工程依赖模块。因此多模块工程存在消费本地 Maven 仓库中旧模块产物的风险。该代码缺口已确认，但目前没有收到用户 IDEA 与 No-ide 两份完整启动日志，不能确定这就是本次版本差异的实际原因，也不能把构建插件版本当成应用版本。

此日志显示补丁不宣称修复模块产物陈旧问题。不擅自升级项目 Spring Boot、JDK、依赖版本，亦不清空 .m2 或重置用户代码。需要对比工作目录、启动主类、classpath 中同工程模块路径、实际 JDK、Maven/Spring profiles、配置文件与端口，再确定修改。多模块验收应先在本地仓库预置旧 sibling JAR，修改 sibling 源码，验证应用实际响应来自新源码，而不只是编译命令退出码为 0。
