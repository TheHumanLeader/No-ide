# v0.4.4 增量构建设计与验收目标

用户要求：改少量代码验证时，不能每次全量 clean/build；同时不能重新引入旧 JAR、已删除类/资源和旧业务处理器问题。日期：2026-09-22。此文档为实现设计，不预先宣布 CI 成功。

## 日常操作

运行/增量构建默认内容指纹判断；清理重建独立且需确认。日志显示本次选择及复用模块、原因和构建检查耗时。进程启动到 TCP 响应另列时间，不能把编译加速说成 Spring 初始化消失。

## 正确性策略

读取 Maven 生效后的 POM/profile/目录/依赖关系。建立一次可信基线；模块源码、资源和构建输出/已安装制品记录 SHA-256。共享基类、常量、公开方法及删除操作不猜 Java ABI：改变模块及依赖它的下游模块都清理重编，未变上游模块不参加本次生命周期。

缓存存于 No-ide 的本机数据目录，不进项目源代码或 Git/SVN 分组。构建前先记 dirty；成功后重新检查输入与环境才记录可复用状态。失败、取消、原地替换本地 JAR、删除 target、在停机期间改文件，都不能仅凭旧成功标记跳过。

POM、JDK、Maven、settings、构建环境或已解析外部依赖变化重新确认基线。自定义插件、构建扩展、未解析路径、外部链接或超过边界的布局保守处理并明示，不把“没有扫描到”当作没有变化。

目前为模块级增量而非 Java 单文件增量；Spring Boot 仍是构建后重启，未实现 HotSwap。仍使用原项目构建目录，不承诺事务化发布或运行进程看不到部分磁盘变化。远端 SNAPSHOT 不承诺每次强制刷新，源码一致性以已选择本地工程与解析依赖为边界。

## 验证目标

真实 Spring Boot / Maven / Java 8 合成多模块工程，带一个上游稳定模块和一个无关损坏模块。测首次基线、无变化启停与执行器重启、保留时间戳的源码编辑、入口模块编辑、共享常量变更、真实 WS 响应、删除类/内部类/资源、替换已安装 JAR、删除编译输出、编译失败与重试、明确确认全量修复。检查未编译模块的实际 JAR 字节及修改时间，不以日志横幅代替执行证据。

用户的五分钟包含哪些部分需实测；历史日志的 Spring 启动约94秒是另一部分开销，不能承诺只改构建计划就瞬时更新。用户业务日志和工程不进入公共仓库。
