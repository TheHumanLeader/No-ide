# v0.4.1：批量分组、运行配置与 Maven 启动修复

## 交互

点文件整行立即勾选，选中样式与复选框一致。支持 Shift 范围选择、全选、反选、清空，以及文件/目录名筛选后全选。底部固定显示已选数量、目标分组和移动按钮。拖动保留为备选，不再要求逐条拖动。

分组只改变本机归属：单次最多 2000 个路径，一个请求、一次配置保存。不调用 Git/SVN 客户端或 status，不刷新整个工作台。不要求版本控制客户端可用。Diff 单独防抖，最多一个执行中请求和一个最新待处理请求，选中反馈不等待 Diff。

SVN 纳入版本控制、Git 暂存均标明“不提交”，放入独立的版本控制操作区。提交选中文件与提交整个分组是不同按钮，均有确认步骤。提交仍保留原有安全限制和实际复验，不因优化选择速度而绕过确认。

## 运行配置

运行台直接展示已有配置，显示入口、工作目录、运行环境、构建工具和关联实例。可以编辑、复制和创建实例，实例的配置名称也是编辑入口。“更新配置”改名为“重新构建”，与编辑区别。

编辑保留配置 ID 和关联实例，不再因为重新选择入口而创建重复配置。保存现阶段仍要求先停止本项目实例。

## Maven / Gradle

构建工具与 JDK 分开配置。支持本机有界发现、安装目录选择、真实版本检查。优先级为运行配置指定、项目包装器、全局指定、自动发现。手动失效不悄悄换版本。Maven 可选择已有 IDEA 安装目录以定位内含的 Maven。

Maven settings.xml 和本地仓库支持文件/目录选择；只保存路径，不在界面读取凭据。程序不存在的错误包含实际路径和工作目录，失败构建同时保留 stdout/stderr 尾部。

## 验证设计

新增 tests/selection.test.js 与 tests/fix-041.py。后者使用真实 Git/SVN 的 150 个临时变更文件，测试一批移动、请求次数、无客户端时分组、重启记忆与未提交源码；实际 Spring Boot 2.7.18 / JDK8 / Maven 项目测试启动及编辑参数后运行。对应 CI 和报告为成功与否的依据；此文不预先宣称运行通过。

不自动点击 OS 文件对话框，不接触用户工程与私有仓库。Windows Server CI 不代替用户 Windows 11 桌面验收。运行包未签名。GitHub Pages 仍是静态演示，实际操作须使用本机包。
