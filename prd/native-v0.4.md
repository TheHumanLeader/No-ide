# v0.4：自动配置、多版本环境与持久化变更分组

## 本版操作

运行环境：检测本机，或选择安装目录添加 Java / Node.js / Python；支持多版本、别名、类型默认值，以及配置和实例的下拉选择。Java 普通主类由配置 JDK 编译，实例运行版本不得低于编译版本。不会修改系统环境变量，不自动下载安装。

运行配置：选择项目后静态扫描常见 package.json scripts、Maven / Gradle 入口、Java main / JAR、Node 与 Python 文件。限制扫描深度、条目和字节，忽略依赖与构建目录。可另选模块目录或入口文件，不要求重复输入项目绝对路径。入参、环境变量、JVM 选项、系统属性由可视化行编辑器生成；保留高级原始命令方式。

代码管理：Git 与 SVN 都使用本机变更分组，默认归入“默认”。支持新建、重命名、删除分组，拖动和批量移动。文件变为干净后仍保留归属，重启后再次修改仍属于原组。不是 .gitignore / svn:ignore，也不会移动磁盘文件。每个仓库独立记忆，单次不跨仓库提交。

提交只选择当前组或本组勾选文件。Git 整文件提交使用当前工作副本内容，不是逐行/逐块提交；其他组即使已经暂存也不能夹带。SVN 使用明确文件列表，不递归提交目录。确认后分组变化会使确认失效。打开仓库时安全地回到默认组，不自动恢复上次特殊组的提交选择。

## 交付与验证

打包版本从 Cargo.toml 读取，build.json 记录提交与流水线。Windows 包包含 no-ide.exe、Start-No-ide.bat 和完整 web/，不需要安装 Rust。

新增真实验证脚本：tests/workbench-v04.py（运行环境与 Git/SVN 分组）、tests/browser-v04.py（真实前后端可视化操作）。v0.3 的 tests/native-browser.py 保留作历史测试，其旧页面选择器不再用于新版验收。旧后端回归仍由 tests/backend-smoke.py 执行。

是否通过以该提交对应的 CI 日志及 JSON 报告为准，本文件不提前宣布测试成功。OS 原生选择窗口、用户 Windows 11 桌面、外部私有认证服务器与长期负载仍须人工验收。Intel Mac 的既有启动问题未因新增界面而视为解决。

升级前关闭旧执行器，新包解压到独立目录；既有项目配置沿用系统用户目录中的 settings.json。旧版不应继续写入新版配置。代码提交和推送会真实发生，先使用测试工程。
