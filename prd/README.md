# No-ide · 产品需求

状态：需求已确认，前端交互原型阶段。归档日期：2026-09-20。

## 1. 产品定位

不再为了运行、构建和查看结果而打开 IDEA。No-ide 是面向开发者的轻量代码运行工作台，不是另一套网页版 IDE。

核心闭环：AI / 外部工具修改项目 → 自动构建 → 更新程序 → 检查就绪 → 查看结果和错误 → 继续修改。

用户优先关心操作和结果，不需要了解内部实现。所有内部复杂度应由工具承接，界面以中文、直接操作、明确反馈为主。

## 2. 已确认需求

- Web 前端使用 Quasar / Vue 3，后端计划使用 Rust / Axum / Tokio。
- Windows 本机优先：浏览器负责操作，本地执行器负责访问工程目录、调用工具链和管理进程。
- 支持 Java 单体、多模块、Spring Boot、分布式多服务开发、Android；支持浏览器 JavaScript、Node.js、Python；允许后续扩展语言。
- 低资源占用、不卡顿；不默认加载全工程索引、不常驻所有语言服务、不引入独立数据库服务。
- AI 编辑工具与本产品解耦；首版不内置聊天窗口。
- 先归档需求，先做可操作前端，再接真实执行器。前端不是静态设计图。

## 3. 面向用户的主要操作

1. 添加项目或工作区，选择已有运行配置。
2. 一键运行、停止、重新运行单个服务或整个工作区。
3. 开关自动更新，查看文件变化、构建、更新、就绪各阶段。
4. 查看分服务日志，搜索、筛选、暂停滚动、清空展示、复制错误上下文。
5. 打开应用预览、查看接口响应或设备运行结果。
6. 查看更新失败原因；构建失败时明确显示旧版本是否仍在运行。
7. 配置运行命令、环境版本、端口、更新模式、监听范围和服务依赖。
8. 查看工具链与 Android 设备；未连接执行器时不展示虚构的检测结果。

## 4. 热运行语义

必须区分，不使用一个“热更新成功”掩盖实际行为：

| 类型 | 基础能力 | 明确边界 |
| --- | --- | --- |
| 浏览器 JavaScript / Vue / Quasar | 接管已有开发服务器的 HMR | 是否保留页面状态取决于实际改动 |
| Node.js | watch 或已有开发命令 | 一般为进程重启，不保证内存状态 |
| Python | 脚本重跑或框架 reload | 不宣称通用原地替换 |
| Java | 构建后重跑；后续受限 HotSwap | 标准类重定义有结构修改限制 |
| Spring Boot | 编译后 DevTools 应用重启 | 不等于所有对象和状态保留 |
| Android | 构建、选设备、安装、启动、日志 | 自动部署不冒充原地热替换 |
| 分布式项目 | 多服务编排和独立更新 | 首版是开发工作区，不是生产发布平台 |

界面状态：待运行、构建中、更新中、等待就绪、运行中、已停止、更新失败。分别展示“已热替换”“已重启应用”“已重新部署”“更新失败，仍运行旧版本”。

## 5. 核心工程约束

- 源码变化必须触发真实构建；进程启动不等于服务就绪。
- 每服务最多一个构建任务；连续文件变化合并，队列有界；明确的批次完成信号优于猜测安静窗口。
- 不重复启动项目已有的文件监听器；避免每次修改都 clean / 全量打包。
- 隔离构建产物和发布时机，构建失败不抢先终止可工作的旧版本。
- 区分代码构建依赖和运行服务调用依赖；按实际影响更新。
- 日志内存缓冲按字节限额；历史日志轮转；前端虚拟滚动；推送队列必须有背压。
- 管理完整受控进程树；区分应用、构建任务和允许复用的守护进程，不误杀其他工具进程。
- 仅按需启动工具链；运行配置可独立选择 JDK / Node / Python 环境。
- 后端空闲 50 MB 仅作为待验证预算，不是已实现指标；分别统计控制台、后端、工具链、实际应用的占用。
- 默认监听本机，校验访问令牌和来源；首次执行项目信任确认；预览页面与控制接口隔离；敏感日志脱敏。

## 6. 架构方向

Quasar 控制台 → HTTP / WebSocket → Rust 本地执行器 → 语言适配器 → 项目原有 JDK、Maven、Gradle、Node.js、Python、Android SDK。

首版配置采用项目文件，不引入独立数据库服务。后续扩展远程执行器、受限 Java HotSwap 和调试能力。

适配器职责：识别项目、检查环境、生成任务计划、声明更新能力、执行和停止、检查就绪、解析错误。

## 7. 前端交互原型要求

默认明亮粉色，中文操作，清楚的服务列表与结果面板。编辑器和文件树不是首页中心。

交互原型允许模拟启停、更新、错误和日志，但必须在界面持续标注“交互预览 · 未连接执行器”。示例工程、日志、响应和更新时长不代表真实运行。不得声称已检测本机环境、执行编译、访问项目或连接 Android 设备。

原型要能实际点击并观察反馈，包含正常、停止、失败、空状态；可直接打开体验，不要求用户先安装 IDE。

## 8. 分阶段验收

### 第一阶段：前端操作体验

可操作的工作区、服务启停、热更新过程、日志和问题、配置、添加项目、工具链占位、主题与布局；明确模拟边界。

### 第二阶段：真实闭环

不打开 IDEA，修改真实 Spring Boot 项目的 Java 代码，自动构建并更新，通过接口响应确认新代码生效。同时接通 JavaScript / Node.js / Python 基础运行。

验证编译失败保留旧版本、重复修改不并发堆积、反复启停无进程残留、持续日志内存不无限增长。

### 第三阶段：扩展

多模块与多服务、Android 构建部署、远程执行器、受验证的 Java 原地替换、按需调试。
